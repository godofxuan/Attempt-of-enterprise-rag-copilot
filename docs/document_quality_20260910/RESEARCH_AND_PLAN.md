## 1. 先用直白的话说明目标

我们需要的不是“支持更多文件后缀”，而是确保用户上传的资料经过解析和切块后，关键事实没有丢失、错位或被猜测补全。

例如“上海 | 550”只有与“住宿上限、元/晚、普通员工、2026 年制度”正确关联，才是能支持回答的证据。把这些字抽出来，不等于保留了这个事实。

本方案解决三个业务问题：

1. 表格原本可读，但切块时丢了表头、单位、条件或整张表。
2. PDF/扫描件没有可靠抽取，系统却只显示“导入完成”。
3. 文件更新或重新解析后，无法清楚追踪使用了哪个原文件、解析器、chunk 和索引版本。

第一项优先修复；第二项用一个解析候选做有限对照；第三项复用现有生命周期，不另建一套平台。

## 3. 调研结论：借鉴机制，不照搬平台

以下为官方资料可确认的能力，不是所有企业内部实践的统计，也不代表本地收益。在线文档会变化，真正实施时要锁定具体版本。

### 3.1 RAGFlow：按文档类型选择解析方式

官方 Parser 文档区分简单 PDF 的 Naive、复杂版面/扫描件的 DeepDoc，以及其他可选解析器；电子表格强调保存行列结构。值得学习的是按文件内容分流，不是把整套 RAGFlow 搬进项目。资料中的优劣描述属于产品说明，不能视为我们的对照实测。[官方 Parser 配置](https://github.com/infiniflow/ragflow/blob/main/docs/guides/agent/ingestion_pipeline/configure_parser_component.md)

### 3.2 Docling：结构化中间结果和带上下文的分块

`DoclingDocument` 区分正文、表格、图片、章节以及页眉页脚，可表达来源和可用的版面位置；其 HybridChunker 支持给分开的表格块重复表头。我们借鉴“先保留结构，再生成检索文本”，不直接用整份 Markdown 代替结构化证据。[文档模型](https://docling-project.github.io/docling/concepts/docling_document/)、[表格分块](https://docling-project.github.io/docling/concepts/chunking/)

Docling 可预取权重并指定本地模型目录；默认首次使用可能自动下载。禁用 remote services 只限制某些发送数据的功能，不等于禁止下载权重。因此必须先审核下载、目录、版本和资源预算，再离线运行。表格识别仍可能列错配，不保证一次成功。[离线运行与表格配置](https://docling-project.github.io/docling/usage/advanced_options/)

### 3.3 Haystack：清洗不是越狠越好

DocumentCleaner 提供空白、空行和重复页眉页脚清理，但官方明确提醒，对 Markdown 过度去空白可能破坏表格、标题和列表；重复页眉页脚处理也要求保留分页标记。不能全局用正则删“看起来重复”的内容。[DocumentCleaner](https://docs.haystack.deepset.ai/docs/documentcleaner)

### 3.4 Unstructured：快速解析、布局解析和 OCR 是不同路径

官方定义了 fast、hi_res、ocr_only 等策略。OCR 负责识别图中文字，布局分析负责区分结构，二者不是同一件事。将其作为技术备选，本轮不同时集成第二套重解析器。[解析策略](https://docs.unstructured.io/open-source/concepts/partitioning-strategies)

### 3.5 Azure：任务成功与内容质量分开管理

Document Layout skill 将文档布局转换为结构化文本/Markdown，可携带位置元数据；索引器分别记录错误和警告，警告可能不终止导入，但仍可能造成异常结果。借鉴“逐文件诊断、可定位失败、受控重处理”，本轮不购买或调用 Azure 服务。[布局技能](https://learn.microsoft.com/en-us/azure/search/cognitive-search-skill-document-intelligence-layout)、[错误与警告](https://learn.microsoft.com/en-us/azure/search/cognitive-search-common-errors-warnings)

### 3.6 外部验证：OmniDocBench

官方提供版面、表格、文字与阅读顺序等标注及解析评估。适合补充真实布局样本，不等于企业 QA benchmark。只做固定小子集，冻结数据和评估版本；代码许可证不能替代逐项核对数据及原始文档的使用/再分发条件。[官方项目](https://github.com/opendatalab/OmniDocBench)

## 4. 推荐方案与不做的事

选择：现有轻量解析器 + 结构保真切块 + 质量报告 + 条件启用的本地 Docling 标准 PDF 管线候选。

不先引入生成式视觉大模型，不换 LLM/embedding/reranker，不增加 Agent、数据库、消息队列或在线全文重解析服务。Docling 所需布局/OCR 权重也属于新增资源，必须在实施授权和预算确认后引入，不以“不换对话模型”为理由隐瞒依赖成本。

不自动“修正”原文金额、日期、制度编号和否定条件。不靠语义摘要替代原始表格。XLSX、公式重算、手写件、图表理解留作后续需求，不纳入首轮通用能力承诺。

推荐数据流（目标设计，尚未实现）：

```text
原始文件 + 主机可信的来源/权限/版本元数据
  -> 现有安全准入与不可变 staging
  -> 轻量预检：格式、抽取覆盖、版面异常线索
  -> 轻量解析；疑难 PDF 在固定预算内进入一次布局/OCR 候选
  -> 结构化内容 + 原文位置 + 逐页/逐表质量报告
  -> 表格/正文分别切块，保留标题、表头、单位和条件
  -> 现有版本治理、缓存、候选不可变索引
  -> 对照验证与发布判断
  -> 现有检索/权限过滤/Guard/证据/引用/回答合同
```

预检只能提供风险线索，不声称自动知道所有漏抽表格。解析器输出的“权限、来源、优先级”等文字均不可信，不能覆盖主机侧授权元数据。新图片/OCR 内容仍是检索内容，不是系统指令。

## 5. 关键设计决策

### 5.1 保留两种表示，但只有一份事实来源

- 原始文件和解析结构用于追溯；检索文本是可重建的派生物。
- 表格检索文本建议包含：文档/章节、表名、原文明确的单位与适用条件、表头及完整数据行。
- 合并表头先保留层级/行列跨度，再生成可读路径；不把复杂结构强行塞进普通矩形列表而丢信息。
- 单位与脚注只在原文绑定明确时关联；不因“位置最近”就确定适用。无法确认记 unknown，不补成元、不将空单元格填成 0。
- 超长行/单元格不得静默截断，必须有预算超限或可追溯拆分结果；每行进入候选库的覆盖需要可检查。
- 避免同一表格同时作为普通全文切片和独立表格无控制地重复入库。去重不能跨文档授权/版本边界。

### 5.2 跨页先关联，再考虑合并

只在同一合法文档 revision 内检查续表。综合重复表头、列布局、表名/续表标记和页面位置等证据，保留各段页码与原始单元格映射。列数相同不足以自动合并。

第一轮允许只建立“候选续表”关系而不拼接；无法可靠判断时保留两个段落并标记歧义。禁止跨 policy/租户/版本拼表。跨页关系需要多位置证据，不能伪造成一个连续字符范围。

### 5.3 最小数据模型，不重建 document platform

优先复用 `ParseResult`、`ParsedTable`、`ParseWarning` 和现有版本记录。原矩形模型无法表达的信息，可先存实验 sidecar，用 raw SHA、parser/config hash、table/block ID 绑定。

候选验证成功后才设计最小、带版本的生产扩展，例如 block 顺序、header paths、cell spans、多个 source spans、单位/脚注关联及解析状态。旧数据仍按旧 schema 验证；不能在 `extra="forbid"` 模型中偷偷塞入未知字段，也不在 string metadata 里藏一套无校验协议。

新 locators 要端到端穿过 chunk、navigation、evidence packet 和 citation verifier。没有改造对应校验前不得宣称实现了单元格/跨页精确引用，也不得放宽原引用标准来让新证据通过。

### 5.4 质量状态与发布状态分开

建议新增质量报告的决策为 `ACCEPT`、`REVIEW_REQUIRED`、`REJECT`，另有 `UNKNOWN` 观察值；它不是替换现有 staging/quarantine/revision 状态机。

- 安全失败：沿用现有拒绝/隔离逻辑，不尝试“修复后放行”。
- 有内容却抽取为空、结构错位、单位绑定不明：记录具体页/表/原因，限制发布或要求复核，不能标成完整成功。
- 真实空白页、非关键装饰噪声：允许按固定策略带警告，不把所有 warning 都变成拒绝。
- 原文业务事实可疑：交资料负责人确认；开发者或 LLM 不能代替制度制定者。
- 新 revision 处理失败时保留上一有效快照，但必须结合原时间/版本政策处理；不能因“保留旧索引”就向用户保证旧制度仍有效。

需要记录分母：提交文件、解析成功、质量通过、待复核、拒绝、实际索引文件以及用时。不能删掉坏文件后，只对剩下的文件报告 100%。

### 5.5 部署和资源约束

- 重解析发生在离线入库，不放进每次提问的 HTTP 请求中。在线延迟仍会受 chunk 数量/内容影响，必须测量。
- 单个候选解析器；一次候选处理失败后结束，禁止在多个解析器间无限重试。临时错误与确定性坏格式错误分开记录。
- 预检/渲染本身也接触不可信文件，不能在安全预算之外先完整渲染。文件字节、页数、图片像素、CPU/内存、执行时间和输出量均需上限。
- 在现有边界中限制网络；禁远程解析服务，同时验证不会偷偷下载权重。模型/依赖下载单独审批和校验。
- 全部新依赖环境、模型、缓存、临时渲染页、索引和证据放 D 盘。实施时显式设置模型 artifacts 路径、HF/pip 缓存和进程 TEMP/TMP，并检查实际写入，不能只设置一个变量就声称绝不写 C 盘。
- 先使用隔离实验环境，不升级主 `.venv`；版本、许可证、磁盘/内存预算不满足就记录阻断，不扩大依赖试到成功。

## 7. 小规模但完整的验证设计

### 7.1 三类证据不能混用

1. 历史故障与已用过的 FinanceBench/企业案例：开发定位和回归，明确 RETROSPECTIVE；不冒充新独立测试。
2. 新建受控文档：覆盖机制边界，原始表格/正文由确定性结构生成并有 gold。能证明固定场景，不能证明真实企业普适效果。正文不得含 gold IDs 等评测捷径。
3. 真实公开布局样本：优先评估 OmniDocBench 固定小子集的可用性。数据版本、许可、历史消费情况和文件摘要先登记；第三方预训练污染未知时如实声明。其表格标注不能直接当成现成 QA 标签。

Pilot 建议六类各 4 份，共 24 份，每份 2 个问题：干净文本/规则表格、Markdown/长行、Word/HTML 条件和脚注、文字 PDF/多栏、扫描/图文混合、跨页/复杂表头。至少 8 问为确实缺单位/条件、需要澄清或不能作确定回答的反例。多标签记录，不能因转换格式把同一原文算成多个独立样本。

将 12 文档/24 问作为 DEV，12 文档/24 问作为候选最终检查；按原文/模板族分组切分，不把同一文档的干净版与损坏版分到两边。最终检查标签由独立保管者/评估流程保管；若开发者或执行模型已经读过，则改称开发回归，不伪称 blind holdout。没有人类确认的真实文档 gold 标为 NOT_HUMAN_VERIFIED。

最终检查不是“再看结果继续调”的开发集；配置冻结后只做一次计划内评估。样本不足以证明稳定收益时保留限制，不能无限迭代直到变好。

### 7.2 对照组：把解析和分块收益拆开

| 组别 | 解析 | 分块 | 用途 |
| --- | --- | --- | --- |
| A | 当前解析器 | 实际基线配置 | 真实 reference |
| B | 当前解析器 | 结构保真候选 | B-A 衡量分块贡献 |
| C | Docling PDF 候选；其他格式不变 | 基线分块配置 | C-A 辅助定位解析贡献 |
| D | 同一 Docling 候选 | 与 B 相同的结构保真配置 | D-B 衡量此配置下解析增益；D-C 衡量分块增益 |

条件不适用的文档仍保留在同一总分母中，并另报 PDF/表格子集。A 解析失败不能从 paired 集中剔除；记录无可用证据，并按原任务 rubric 评价回答/拒绝。

固定 LLM、embedding、reranker 的实际标识/摘要、候选深度、top-k、prompt、seed、硬件和预算；除被比较因素外不同时改检索策略和回答合同。回答合同升级若另有必要，必须单独实验，不能混成解析提升。

解析变化会改变 chunk ID；qrels 应绑定原始文档/页/表/事实，而不是沿用旧 chunk ID。检索排序与数据导出不得读取 gold。样本级结果按原文分组做 paired bootstrap，重复生成不当作独立文档扩大样本量。

### 7.3 指标与分母

| 层级 | 主要指标 | 解释 |
| --- | --- | --- |
| 解析 | gold 关键事实保留率、数值-单位-行列对应正确率、必要页/块覆盖、错误关联数 | 有多少真实信息被完整且正确抽出；仅字符量不算正确 |
| 表格结构 | 已标注表格的 cell/header/span 对应；可兼容时使用官方 TEDS | 不自行把字符串相似度命名为 TEDS；不兼容则标 NOT_MEASURED |
| 分块 | 行覆盖、表头/单位/条件共同保留率、重复量、超预算/截断数 | 检查解析后是否又丢信息 |
| 检索 | Evidence/Page Hit@1/3/5、Macro Evidence Recall@5、nDCG@5 | qrel 粒度预先固定；页面命中不能算命中该页所有表格单元格 |
| 回答 | 数值/单位/条件正确率、用户诉求覆盖、引用精确/召回、无据断言、错误宣称答全率 | 优先结构化 gold 和可解释规则；自由文本仍需人工核查规则误判 |
| 拒绝 | answerable 覆盖率、refusal precision/recall、partial 比例 | 不能靠全部拒绝提高“没有幻觉”的分数 |
| 运行 | 入库秒/页与 p95 秒/文档、峰值 RAM/VRAM、磁盘与索引体积、在线 p50/p95 | 分开测冷启动/预热；解析成本和在线查询成本分开报告 |
| 可靠性 | 来源追溯、权限隔离、版本/删除/回滚、错误与重试可见性 | 有测试才能称本范围内验证，不称绝对安全 |

错误宣称答全率至少报两个分母：错误 answered / 全部问题，以及错误 answered / 全部 answered；gold 标明可回答/不可回答，避免将正确保留 partial 当作漏答。

### 7.4 必须覆盖的反例

- 首行并非表头、多级/重复表头、合并单元格、空格与转义竖线、代码块里的伪 Markdown 表格。
- 空值、0、负数、小数点、百分号、日期、货币、万元/元、每晚/每次、不得/仅限等不能被清洗改变。
- 表格在文档中部、末尾、独立于段落；长表、超长行和跨 token 预算。
- 页脚与表头重复；正文也重复相同关键条款，不可被全局去重误删。
- 空白页与扫描内容页；多栏顺序；低清晰度识别失败必须有记录。
- 同列数但不同主题的相邻表、不同单位的续表、不能判断续表的样本。
- 解析内容含提示注入、外部链接或伪造权限字段；不触发网络、不提升权限。
- 相同原始文件跨租户、不同 ACL/版本；不能通过复用缓存产生可见性串用。
- 改 parser/options/weights 导致正确失效；重复同一合法任务不重复激活；删除/回滚不残留不可见旧 chunk。
- 超时、内存/输出预算、损坏文件、崩溃和中断时不发布半个索引；失败项不得从统计中消失。

### 7.5 门槛与停止规则

以下是待在 DQ0 冻结的项目验收规则，不是行业统一标准，也不是本轮成绩：

1. 固定确定性夹具不得新增数值/单位/否定条件损坏、遗漏行、错误续表、权限泄漏或伪造引用。所有未过项保留原始结果。
2. B 必须修复真实复现的结构丢失问题，且 clean 对照不丢原已支持事实；没有可复现损失，不为了重构而重构。
3. D 只有在真实 PDF 子集增加有效事实/回答支持，且代价在冻结资源预算内，才值得接入。只多抽字符、只提高成功导入数不够。
4. 在相同问题集合报告全部恢复和退化。Recall/回答 nominal gain 但置信区间跨 0，标为有限样本改善，不写稳定/显著。不机械要求统一 +5pp，也不能用小幅涨分掩盖严重错误。
5. RAM/VRAM、磁盘、单文件时间与在线 p95 的数值预算由 DQ0 实机基线确定，在候选评测前写入协议，不能见到结果后放宽。在线 p95 小样本噪声须单独说明。
6. 未验证的新 schema、错误缓存复用、索引回滚失败、安全退化、预算无法限制均阻止发布。
7. 若布局解析不能带来可解释收益，保留 DQ1 有效修复及诊断报告，放弃重解析候选，不增加第二/第三个解析器继续扫。

## 8. 交付、记录和宣传边界

实施阶段在候选工作树内另建版本化实验/证据目录；不得覆盖历史报告。建议产物：

- `START_STATE.json`：HEAD、dirty patch、源码清单/摘要、实际入口、索引/配置、环境和依赖。
- `CORPUS_MANIFEST.json`、`PROTOCOL.md`：原始来源、许可、sha256、数据历史、分组和 rubric。
- `FAILURE_ANALYSIS.md`：原文 -> parse -> chunk -> retrieval -> answer 的失效点，分别标 observed/code-derived/unknown。
- `PARSE_QUALITY.jsonl`、`CHUNK_COVERAGE.jsonl`：逐文档/表/行的诊断、路由、耗时和状态。
- `ABLATION_RESULTS.json`、`PER_QUERY.jsonl`、`BOOTSTRAP.json`：所有组、所有样本、拒绝和失败的完整分母。
- `TEST_RESULTS.json`、日志、JUnit、`MANIFEST.json`：本次真实执行证据与文件摘要。
- `DECISION.md`、`LEARNING.md`：改哪里、为什么改、替代方案、问题、失败/收益原因、未验证事项、保留/不合并内容。

没有真实原始证据的指标标 NOT_RUN/NOT_VERIFIED，不制造空文件冒充产物。数据不足/环境不支持可以是合法停止结果。

成功后可以展示“有来源追溯和失败处理的文档入库”“具体样本上的表格保真和问答改善”；不能提前宣传任意 PDF/扫描件可用、真实企业生产验证、100% 正确率或已解决所有跨页表格。

WixQA 旧 Recall/nDCG 不会因为新增 PDF 解析器而自动提高，也不作为本次解析收益证据。简历只在最终证据产生后更新；不把调研、实现存在或单测通过写成效果提升。
