# ESA 0.2.0 本地演示版

最后源码提交、安装检查和运行状态以STATUS.md为准。默认一个FastAPI应用和一个固定DATA_DIR。

## 实际能力

| 组件 | 职责 |
|---|---|
| 独立RAG | MD/TXT/PDF/DOCX导入、真实本地FAISS/BM25、来源回答、追问、历史版本和有界深入查找 |
| Service Agent | 用户明确服务和范围，9B原生工具选择，真实观察送回下一步；不是预填工具顺序 |
| 借用 | 资格/库存/本人申请、补参、预览、改期、精确确认、唯一PENDING_APPROVAL、幂等读回 |
| 合成IT报修 | 本人设备、描述、影响程度、预览、确认、本地OPEN待受理工单；不改借用资格 |
| 共同宿主 | 任务、表单、工具循环、SQLite事务、版本、精确确认、取消、run fence和命令账本 |
| 共同知识 | 两入口复用同一KnowledgeService、Guard、完整来源单位和唯一publisher |
| 更新/反馈 | 指定目录增量、原代次保留、未变chunk缓存；反馈生成expected为空的待审候选，不自动跑模型 |

FAISS是安装的开源库，知识索引由本机bge-m3对导入文档生成，不是下载的别人知识库。
旧LangGraph等为legacy可选资产，默认薄循环不加载。模型不能授予权限、代确认或宣布审批通过。

## 可重复的界面演示

1. 按START在明确的TEST目录启动，导入examples/esa/demo_policies两个制度并建立索引。
2. 问借用的资格、期限、日期、数量、待审批和押金规定，打开原来源。
3. 从回答进入借用，明确“预览后精确确认提交”。填合法未来日期和用途；原问题有参数时可由用户勾选提取并检查。
4. 查看实际设备选项并选择，再继续运行。工具进度显示真实工具名和观察，不编造模型思考。
5. 勾确认后改结束日期：勾选清除，旧确认不能提交。生成当前预览，再单独精确确认。
6. 回执为待审批，不是批准、分配或预留；刷新/重启读回同一command。响应丢失重试不新建单。
7. 新建IT报修，设备employee-laptop-1，填描述和影响程度。自然补充后核对新预览并确认。OPEN是待受理，尚未维修。
8. 资料库登记明确选定的目录。改一份文档后同步和更新索引；新问题使用新版本，旧答案仍可看原版本。

以上是用户交互步骤，不是宿主预设给模型的工具调用次序。再次从零演示使用新的TEST目录，旧工单/账目保留。

## 实测与限制

- 未变两文档重建：2次嵌入/3.282s → 0次/0.218s；J12改一份仅重算该chunk。这是具体样例，不是整个Agent提速比例。
- 一次只读备注修改后，实际读取从3类减到1类；模型仍重读规则，chat为2→2，未证明chat或整段时延下降。
- 追问已接通用户上下文。一条“能否按零元”的答案只引用没有规定押金，未直接解释推断边界；原失败已留作待审反馈，未声称全面修复。
- 目录缺失源保留最后导入版本并提示；文档更新但索引未更新时，不给当前问题套旧代次。
- 没有OCR；复杂版面/大库、其他模型完整旅程、Linux、双入口Docker未做本轮验收。
- 本机单用户、合成后端。企业身份、真实外部系统、借用归还/续借/撤销、长期记忆、多Agent未实现；auto仍实验。
- 首次表现层脚本的固定结果名被绿测覆盖，首轮工具输出另存，未冒充恢复原截图；后续改唯一时间戳。
