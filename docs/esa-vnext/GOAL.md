# GOAL：把现有候选变成可持续使用的企业知识与服务工作台

## 1. 北极星

在保留当前本地成果、既有检索与业务实现的前提下，将Enterprise RAG / Guided Service Agent建设为一个可以独立安装、单入口启动、管理知识、推进实际任务、失败后继续使用，并能扩展到第二种业务的应用。

优先级：**稳定启动与数据连续性 > 实际用户旅程 > 清晰模块与成熟组件复用 > 有用的新能力 > 基于测量的优化。**

这不是“无限优化所有代码”，也不是“让所有历史审计指标变绿”。

## 2. 当前连续执行范围

本次授权的完整目标覆盖`ROADMAP.md`的M0—M8：

- **R1，M0—M6：** 单应用底座、知识库管理与统一RAG、完整电脑借用、精简Agent、任务工作台、知识转任务、修改影响分析、真实备选方案、可发布演示。
- **R2，M7—M8：** 以本地合成IT报修实现第二个完整服务；增加明确选择目录的增量导入、实际问题反馈和一次有依据的质量/性能改进，形成可扩展版本。
- **R3：** 团队化、真实外部业务系统、多进程扩容等仅作长期路线。本次不自动实施，不因为完成R2就自行继续建设平台。

R1达到出口时生成一个可运行里程碑，但不因为“第一阶段做完了”就等待用户说继续；依赖允许时继续R2。真实外部条件阻塞时，先完成不依赖该条件的任务，不伪造通过。

## 3. 产品完成条件

### R1应当成立

1. 从最终代码副本按README安装与启动，不依赖作者的绝对路径、测试fixture或另一份隐藏源码树。
2. 默认一个FastAPI应用、固定数据目录；重启不换数据库，不重复seed，不重复嵌入所有文档。
3. 模型不可用时页面、设置、已有资料和任务仍能打开；缺失能力有明确提示，不把假回复当真实模型。
4. 用户可以导入已有解析器实际支持的文档，看到处理状态，选择知识库问答，并打开来源片段。
5. RAG与Service共享同一知识核心和现有结果契约，不把一份答案反复拆解、重写、重审。
6. 借用支持补信息、修改、查询库存/已有申请、形成预览、明确确认、一次业务提交、持久读回；多次正常改期不被任务历史计数卡死。
7. 模型按真实观察选择工具；前后端确定性操作由普通业务代码完成，不靠模型宣称成功。
8. 页面刷新或进程重启后恢复任务视图；中断运行能从已保存的业务事实继续，不重复提交。
9. 知识转任务、受影响步骤重算、真实备选方案完成端到端交互，而不是仅有接口或静态卡片。
10. 至少一条实际配置模型参与的知识问答和借用主旅程运行过；没有可用模型时此项标`BLOCKED`，不能以回放代替。
11. README、一个完整演示、当前分支/commit和可用入口一致；代码可按已授权凭据推feature分支，未推送如实说明。

### R2额外成立

12. 第二服务IT报修使用公共任务、表单、Agent、预览、提交、事件和历史界面；只有规则、字段和业务适配器不同。不允许复制一份TaskAgentGraph或门户。
13. 报修规则、资产和回执使用明确标记的合成数据；创建本地工单不宣称提交真实企业IT系统，也不自动与原借用资格/维修记录联动。
14. 用户选择的本地目录能增量导入；新增、修改、移除有明确定义，不扫描整个文件系统。
15. 从真实使用问题中完成至少一个可演示的质量或性能改进，提供改前改后的相同场景结果；若没有改善则保留更简单版本并写明结果，不为“必须提速”改小任务。

## 4. Codex的自主权

在当前项目内，可自行调整相关模块、接口内部实现、页面交互、配置、依赖声明和局部数据库迁移；可查阅官方文档和开源源码、运行本地程序、构造合成场景、修复新发现的直接阻塞问题。无需为改一个函数、补一项依赖或处理一个普通失败反复请求确认。

计划是目标和边界，不是限制在几个指定文件里打补丁。发现计划中的实现方式不适合当前源码时，选择更简单的等效方案，在STATUS记录原因后继续；保留对用户承诺的行为，不能通过降低成功条件来宣布完成。

涉及不可逆删除个人数据、启用付费外部服务、向真实外部系统写入，或需要新凭据/生产权限时才集中提出一次明确问题。不要关闭执行环境限制、操作其他人的进程或把“自主修复”解释为修改系统与其他仓库。

## 5. 工作循环

每次选一个当前最有价值的阻塞或纵向功能：观察实际现象 → 读相关源码和一次最小复现 → 形成可证伪的原因判断 → 修改共同实现 → 跑相应检查和真实入口 → 更新当前状态 → 继续下一项。

连续两次同类修补仍失败时，不继续增加关键词、异常白名单或重复重试；回到调用链、数据流、版本或组件边界，改变诊断方法。正常的局部问题自行解决；所有任务都真正依赖外部资源时才停在`BLOCKED_EXTERNAL`。

用户新消息、客户端中断或预算上限必须得到尊重。写好当前状态不等于任务完成，更不等于关闭客户端后仍保证运行。

## 6. 结束状态

- `DONE_R1_R2`：上述当前范围已实现，实际结果支持完成，剩余内容明确属于R3。
- `PARTIAL_BLOCKED`：可做的已推进，仍缺模型、权限、数据或外部服务；列出具体影响和最小解除条件。
- `PAUSED_WITH_STATE`：用户暂停、预算/会话限制；保留分支、正在处理的文件、最近结果和下一条可执行动作。

不因“写完计划”“创建了所有目录”“测试数量很多”“完成离线假模型流程”而将整个Goal标为完成。
