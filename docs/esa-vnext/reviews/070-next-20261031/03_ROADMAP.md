# 14项有出口的实施路线

三个交付出口独立：A远端同步；B默认产品可合并/可试用；C解释实验有明确结论。**C失败不反向禁止A/B。**

|阶段|ID|内容|出口|
|---|---|---|---|
|立即同步|A01|核对真实分支与公开内容，push＋Draft PR|真实远端分支SHA及PR链接；缺权限写精确错误|
|立即同步|A02|建立产品CI与独立实验检查|默认共享代码、构建与恢复有必需检查；实验失败透明|
|默认闭环|B01|部分交付、仅重试未完成项|原API复现不再DONE+409|
|默认闭环|B02|明确按钮调用准备业务用例|字段/设备确定后预览不依赖模型再授权|
|默认闭环|B03|待交付项与finish后置条件|模型漏一项不假称整轮完整|
|默认闭环|B04|短事务与WAL真实恢复|原恢复路径不因持锁返回裸500|
|默认闭环|B05|运行版本识别与可理解升级|新包不会静默伪装成已运行的新版本|
|默认闭环|B07|部分结果与升级前端交互|单输入框、明确下一步、来源与预览保留|
|默认闭环|B06|最终默认主旅程回归|当前默认模型和同数据借用/报修可继续|
|独立实验|C01|知识主题与上下文归属|借用/报修证据不混作同一主体|
|独立实验|C02|稀疏有依据表达|减少硬语义词表与重复协议|
|独立实验|C03|同条件配对质量结论|真实改善才转正；无改善保持关闭|
|发布收尾|D01|最终包、升级和原生体验|真实最终实例版本、正常重启、数据保留|
|发布收尾|D02|完成PR与发行说明|默认目标达成后按授权合并；不等待实验无限调优|

详细依赖、模块、交付物、验收在work_items.jsonl。B07排在B06前是依赖顺序，不是遗漏。

## 怎样持续推进
1. 先A01，不能以未达到formal070推迟同步。没有凭据时保存真实阻塞并立即做A02/B。
2. B01—B03优先解决默认功能真实完成；B04/B05可在明确模块边界内并行，别并行修改同一个Store事务。
3. B06/D01验证同一候选；文档差异可以单独提交，但测试不能把不同运行版本混成一次通过。
4. C可并行小范围推进；其失败只影响新解释成为默认，不能阻止修复版入库。
5. D02的依赖不含C03；若决定本轮发行不启用解释，README必须如实说明。
6. 默认scope达成后结束本轮Goal，不继续自动建设0.8或第三业务。留下可选研究issues即可。

## 不新增的门槛
不要求遥远历史main全部实验得分；不要求测试数量增长；不要求完整private数据公开；不要求每个小提交重新打包Windows；不要求人工复验所有不相关桌面路径。
