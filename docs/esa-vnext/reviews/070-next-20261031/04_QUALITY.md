# 全面但有限的质量计划

## 1. 使用真实层级
默认产品程序测试：当前应用工厂、原领域服务、真实临时SQLite；只替换明确的外部模型/网络边界。修复影响的测试每次运行，其余在阶段完成时运行。
浏览器：当前React构建＋当前产品API，临时工作区；检查实际可见操作与后台结果。不是纯静态截图，不在私人活动库里为自动测试改数据。
真实模型：已有Ollama模型/索引，记录真实调用和内容，不与替身测试相加。优先原失败轨迹和默认主旅程，不每次小改跑全24例。
Windows：当前最终包正常首次打开、重复打开、旧库升级、移动后定位、中文输入法最小实际检查。没有桌面环境就标未验；不换工具规避平台拒绝。

## 2. 默认必需检查与实验检查
- default必需：应用入口、API、事务、恢复、shared知识引用和传输、实验开关默认关闭、前端类型/构建、核心浏览器。
- experimental独立：新增解释语义规则及模型对比。保留当前失败测试和原始结果，单独显示红灯，不用skip/xfail或`|| true`假装通过。
- 不能按文件名随便排除整个test_grounded_expression.py：其中开关默认值、共享解析与引用的回归仍属于default。按实际覆盖的代码拆分，分类原因写一段。
- Draft PR可在默认仍失败时打开；合并默认产品时需default真实通过。Git push本身不以模型语义测试为前置。
- 不给“所有旧项目测试”一票否决而不说明支持范围；当前公开承诺的兼容功能仍需检查或明确迁移。

## 3. 本轮16项行为规格
见acceptance_cases.jsonl。这些是待实施/待运行规格，不是本次已执行16个测试。重点三元检查：用户看到什么、数据库存了什么、下一次还能做什么。

## 4. 真实质量的最小有效对比
先分析已暴露的开发与留出失败；它们现在只能当回归。
用一组相同的典型问题对default与简化候选比较，保持模型/提示输入证据/索引一致。每例记录直接回应、关键条件、主体、来源、未知处理，不用answered计准确率。
开发固定小集合做方案选择；最后少量从未用来调参的验收输入只运行一次候选比较，有故障保留并定位。没有足够改善就关闭实验，不不停增加题量证明工作。

## 5. 默认发布门槛不再漂移
- 本次partial重试与漏交付恢复机制通过。
- 当前d32后继实际服务中默认知识能返回正确来源、借用和报修的主旅程能继续。
- 幂等提交、读回、改期使旧确认失效、旧数据保留保持。
- 新包与真实运行版本一致。
- 当前README承诺真实，无新解释成功的虚假宣传。
Windows正式stable另外完成原生首次/自动开页/输入法；未验时预发布如实标注，不阻止源码分支同步。

## 6. 失败怎么处理
先定位责任层；不删除断言，不缩小资料改成容易问题，不重置活动库绕过旧申请，不把环境依赖错误写成产品缺陷，也不当通过。
连续两次相同补丁无改善时，停止扩大词表/timeout，重新检查真实请求、证据、输出和发布差异。无需新建审查平台。
