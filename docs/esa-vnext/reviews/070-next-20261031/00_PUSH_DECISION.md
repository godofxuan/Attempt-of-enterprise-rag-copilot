# 推送不是正式发布的同义词

## 明确决定
| 动作 | 现在的决定 | 条件 |
|---|---|---|
| 推送当前候选源码到feature分支 | 应立即做 | 确认目标仓库/分支；一次检查公开内容；真实凭据可用 |
| 创建Draft PR | 应立即做 | 写清默认功能、实验默认关闭和已知问题；不声称已全部通过 |
| 合并main | 修复默认通路后准备 | 当前产品CI、默认知识与业务关键旅程、数据兼容；按用户合并权限执行 |
| 发布可试用pre-release | 可在候选冒烟完成后做 | 标记预发布及真实未完成项；产物真实存在 |
| 正式稳定0.7 | 尚需有限的完成项 | 同一最终包原生启动/恢复、当前默认模型主链、核心行为有效 |
| 打开新解释为默认 | 暂不做 | 主题归属、条件和比较有真实改善；不能靠partial标签掩盖错误正文 |

不设置“战胜整个历史main”或“未来所有功能完成”作为推送条件。main兼容检查只覆盖此次承诺保留的公开功能及实际数据升级；旧实验排行榜不是长期阻塞。

## 本机执行步骤（不含破坏性命令）
先在真实仓库读取：
```bash
git status --short
git branch --show-current
git remote -v
git fetch origin
git log --oneline --decorate origin/main..codex/esa-061-070
git diff --stat origin/main...codex/esa-061-070
```
检查待公开提交和新增文件，不公开.env、活动数据库、个人调用原文、模型、完整审核包。不能仅以.gitignore存在来认定历史提交没有私密内容。只做一次针对本次提交的检查，不建新哈希平台。

目标分支无冲突且内容可公开后：
```bash
git push --set-upstream origin codex/esa-061-070
# 已安装并登录gh、仓库和分支核实后：
gh pr create --base main --head codex/esa-061-070 --draft \
  --title "ESA workbench: recovery fixes and 0.7 release candidate" \
  --body-file docs/esa-vnext/NEXT_PR.md
```
`NEXT_PR.md`由06_DRAFT_PR.md核实、替换占位后生成。已有PR则更新，不创建重复PR。若远端同名分支已有更新，先检查分歧并正常集成，不force push；必要时用清楚命名的新feature分支。

推送只传已提交历史，不会自动提交当前7个脏文件；不要为了推送运行git add .、reset --hard、clean -fd。缺凭据时输出真实错误和精确恢复命令，继续本地实现。没有实际push结果，不写已同步。

## Git权限的明确表达
本次交给Codex的任务明确授权它在用户现有凭据与仓库权限允许的情况下推送feature分支、创建/更新Draft PR。合并main、force push和正式发布标签不是默认附带授权。用户已经另行批准这些操作时，按真实授权执行，不能凭空假设。

## 最终default合并的有限门槛
1. 默认配置的核心代码及前端构建/产品测试通过；已知实验失败仍可在非必需研究检查中公开呈现。
2. 本次两个复现修好：部分结果可继续，缺一项不假装整轮完成。
3. 新候选确实启动，默认知识一组、借用/报修主要路径实际运行，旧库可读。
4. README与当前默认行为一致，注明本地单用户/合成业务范围。
5. 不要求实验解释在本轮转正；不新增第三业务或另一个框架作为合并门槛。
