# 下一步实施设计：缩短闭环，而不是增加审查层

## 总体目标
先让源码进入远端协作；再把默认路径中“未做完不能继续”“按钮还需模型批准”“新包开成旧版”三类问题解决。解释创新独立进行，不把它变成所有交付的共同阻塞。
保留单FastAPI、React/TypeScript、Ollama、BGE-M3、FAISS+BM25/RRF、SQLite、原生工具循环、现有领域事务。没有证据不新增数据库、前端运行时、多Agent、长期记忆或第三业务。

## A. 完成交付的对象，而不是再添一个judge

### A1. 在现有协调器中增加轻量交付结果
扩展现有返回DTO，不另建并行流程系统。可表达如下含义（字段名称以已有契约复用为先）：
```json
{
  "turn_id": "...",
  "execution_status": "succeeded",
  "delivery_status": "partial",
  "deliveries": [
    {"kind": "preview", "status": "ready", "ref": "proposal-id", "facts_revision": 4},
    {"kind": "knowledge", "status": "retryable_error", "error_code": "EVIDENCE_INSUFFICIENT"}
  ],
  "next_actions": [{"kind": "retry_pending", "label": "重试解释"}]
}
```
- Run描述本次执行是否正常结束；Turn描述此次答复是否完整/等待输入/部分交付；票据描述实际业务状态。复用当前已有对象，不造第四份事实库。
- 一个完整预览只是一个deliverable。后续解释失败，保留预览、标记部分结果、允许重试未完成部分。
- 回答缺资料但正确说明未知，可是有效的knowledge交付，不强迫通过伪造资料让它complete。
- 状态由TurnCoordinator统一落库，不能在API、Agent与页面各猜一遍。
- 导出DTO与前端同步；正常界面不展示原始枚举或错误堆栈。

### A2. 待交付项如何形成
结构化用户动作和明确任务简报可以确定“准备预览”等要求；自由文本复合输入由同一次主模型响应提供简短的需求解释/动作意向，保存原问。不要额外串联分类器、planner和reviewer。
不要声称所有自然语言目标都能机械验证。宿主可验证已经接受的预览、资料回答和字段更新是否真实存在；对理解本身用代表性语义用例检查。
模型finish或无tool_calls不能把所有待交付项自动改为完成。有缺项时提供当前事实与未交付项进行至多一次针对性继续，仍无进展则partial并显示实际下一步，不能8次重复一段警告。

### A3. 重试只补未完成的部分
原始输入、Deep/KB/事项绑定继续保留。重试取最新业务事实与索引版本。
已完成预览在facts_revision/规则/资源检查仍有效时复用；否则明确作废并重新准备，不用旧快照覆盖新编辑。已提交申请只读回，不重复创建。
重试知识不重新应用原句中的日期变化；明确区分输入已应用、知识尚未完成。
若用户结束事项，知识仍可在会话继续；只涉及结束事项的剩余业务动作应明确终止，而不是重开事项。

## B. 明确点击的操作直接执行普通业务用例

### B1. 提炼PrepareApplication用例
用户已选日期、用途、设备并点击“生成预览”时，不应再依赖LLM愿不愿意调用prepare_preview。复用现有领域服务形成一个准备用例：
1. 读取当前参数、规则、资格/本人设备、排期、已有单据；
2. 缺字段返回结构化fields；已有单返回reference；无库存返回alternatives；
3. 条件成立时调用原事务创建/复用预览；
4. 不提交，不扩大用户允许范围。
前端按钮与Agent工具调用同一用例。Agent仍可在自由文本任务中选择工具、提出问题和比较实际候选；确定性按钮不用额外模型。
不预填一条固定工具剧本冒充模型自主决策，不让前端直接SQL，不复制资格规则。用户明确选择的设备未可用时返回真实结果，不能自动偷偷替换。

### B2. 真实模型失败用例应如何修
原包9f82已读规则却口头表示预览、未形成真实proposal。保留该任务/输入作为回归。
在默认Agent路径上验证两种输入：自由文本准备与直接点击准备。前者允许有界工具继续，后者必须通过普通业务用例完成；不能为修前者把后者也强制交给模型。
工具描述缩成用途、输入、输出；业务限制由服务代码负责一次。上下文只给事实、最新观察、当前待交付项，不在system每步重新堆全部历史警告。

## C. 稳定运行与升级

### C1. SQLite共同连接/事务习惯
继续使用SQLite。先画清实际路径：API→协调器→领域用例→连接；模型账本和事件记录在哪些点写入。
- 所有网络、模型、文件解析在事务外；写事务短且明确提交。
- 同一用例已经持有写事务时，下游使用同连接/事务对象，不再打开另一条等待自己的写连接。
- WAL初始化仍在启动lease下执行，不在每个请求重复设置。
- 可以有有界busy处理，但只对可重试的整个数据库事务；不能重放模型调用或无幂等的外部写。
- 锁争用错误经统一错误映射变成可恢复提示，保留此前的部分结果，不返回无法解析的Internal Server Error。
- 保留现有幂等、确认与读回，不使用sleep、增大十倍timeout或删除锁当根治。
- 默认SQLite足够当前单用户；发现独立证据再考虑扩展，不先加Postgres或写入队列。

### C2. 能辨认自己实际运行的版本
构建时嵌入一次version、source_commit与build_id，暴露到/api/instance与“关于”页面；这不是每文件hash验证。
双击新版时：若同工作区运行旧版，清楚显示已运行版本与本包版本。可选择打开原实例，或在没有未完成业务写时正常停止并换新版。活动run先结束或由用户明确取消。失败时保留数据及错误，不能强杀未知进程。
平台禁止停止操作时尊重拒绝；不换工具绕过。Codex继续可做的实现，并给用户一个明确的人工步骤。
启动验收以实际API报告版本为准，脚本--commit参数只作期待值，发现不匹配应停止评分，而不是给旧进程贴新标签。

### C3. 前端只修关键交互
不再换框架。保持助理/事项/资料库、单composer、按需抽屉。
- 部分交付显示两项结果和唯一下一步，例如“预览已准备，解释失败，重试解释”。
- 生成预览是结构化操作；确认提交保持一次明确动作。
- 页头/设置可看到运行版本；更新时不把新包旧进程混起来。
- Query key继续使用conversation/turn/run真实身份；切换会话不停止后台业务。
- 重试按钮从delivery.retryable得出，不只看run是否failed。
- 错误用中文和可行动按钮，不展示EVIDENCE_INSUFFICIENT裸文本JSON。

## D. 知识解释实验：改总体数据流，停止给词表打补丁

### D1. 先纠正证据主题归属
目前“报修”引用到借用待审批说明：来源真实不代表主体正确。
证据传给模型时显式携带title、section、版本、业务主题和原文。上传资料可从已有metadata复用主题；没有可信主题时保留unknown，不能为了过滤猜一个标签。
当前事项的service_kind为业务问答提供范围；纯知识问题不被历史事项强行锁定。比较题明确允许多个主题，但按对象分组阅读和输出，不能把所有来源拼成一个无主语句池。
不要写if '报修' in question这种企业关键词列表充当通用语义系统。

### D2. 一个稀疏生成契约
在现有AnswerResponse上扩展，不新增第三套writer。生成只需表达：结论/条件/比较块、其source refs、必要未知。
生成正文和证据原文分开：正文回答问题，来源抽屉保留准确原文位置。事实来自当前选中证据，不用用户假设验证客观事实。
运行时保留确定检查：结构合法、source id在当前证据集合、版本与范围有效、必要引用对象存在。数字/否定/词项重叠不是通用语义证明；把相关规则降为定位信号或限于确定的业务字段，不再拼接大量硬拦截。
不要去掉原始来源准入、业务权限或当前事务。这里删的是重复的语义猜测门槛，不是基本业务边界。
不默认增加额外judge、独立writer/rewriter或全局更大模型。相同模型/资料/索引下比较简化前后，只有获得真实改善才启用。

### D3. 评价实际内容，不追求全部变answered
已公开的12留出例现在是回归集。使用其中典型失败先定位主题、上下文、生成或发布哪一层出错。
当前默认和候选用相同问题、原始证据和模型配置配对；解释准确、条件保留、主题不串、直接回应、引用可支持分别评价。
对无法从制度推出的资格不保证批准；资料没写押金不推出免费；基于用户明确假设可以给条件性结论但不能当个人事实。
选择方案之后再建立少量未用于调参的最终验收例，不每个提交重新做整轮真实模型评测。
实验仍未改善则继续显式关闭，保留结论，默认恢复版照样可以合并/预发布。不能把失败实验包装成正式0.7主要功能。

## E. 代码删减与维护
- 不追求删if数量，追求一条规则一个拥有者、一个操作一条用例路径。
- 不把所有历史代码一次ORM重写；沿当前产品入口提取coordinator、usecase、repository、knowledge publisher。
- default与experimental路径及测试明确，不改掉失败断言来“全绿”。共享引用/传输/关闭开关回归必须仍在default必需检查。
- 当前STATUS首页只保留当前版本、分支、运行实例、下一工作项和真实阻塞；旧长日志归档而非每轮重复复制。
- 代码、使用说明、简洁PR、自动化结果是交付主体；不继续把完整调用账本和数十个中间ZIP当主要成果。
