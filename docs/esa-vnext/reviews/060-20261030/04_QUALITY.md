# 完整而高效的质量方案

## 原则

测试服务于用户能否完成操作，不以条数、哈希数量或‘模型返回JSON’作为质量结论。本包24条场景是待实现行为规格，当前运行结果另在evidence。不需要每个代码修改都重跑全模型库。

## 分层与触发

| 层 | 内容 | 何时运行 |
|---|---|---|
| 静态/类型 |受影响Python lint、TS类型、OpenAPI DTO一致性 |修改对应模块时 |
| 领域和协调器 |原事务、请求快照、重试、工具批次、run归属、工作区选择 |相关修改时；可用脚本模型选择，数据库真实 |
| 产品API |实际create_workbench_app、lifespan、SQLite和API；仅外部模型受控替换 |每个工作项/合并 |
| 浏览器 |原React+原FastAPI+临时工作区，真实导航、交互和SSE |每个可运行阶段；CI不借用活动服务 |
| 真实知识/Agent |真实Ollama/BGE/索引，小型标注集和关键任务 |答案协议/上下文改造后，发布前固定一轮 |
| Windows发行 |最终目录的ESA.exe、首次开页、路径/端口/工作区/重启/物理IME |发行候选冻结后 |

不能把模型替身结果和真实模型结果相加宣传。不能把同一104项从不同目录执行算208。有失败先归类环境、fixture、代码或能力不足；不能自动删断言或用永远重试到绿的做法消除记录。

## 自动化入口改进

后端拆分tests/conftest.py的检索依赖，不需要FAISS的产品测试不应在收集时被FAISS阻塞；需要检索的组在受支持3.12环境安装真实依赖。不要向sys.modules注入假FAISS去伪造全套通过。

前端增加正式的@playwright/test配置，保留已有Playwright能力；webServer启动当前产品工厂，测试使用临时DATA_DIR、配置baseURL、明确端口和受控外部模型适配器，不访问个人.private活动库。复用缓存与构建产物，但CI不得复用某个未知本地服务。选择器优先角色/标签，等待实际HTTP/界面状态，不大量sleep。

组件级run hook/DTO可用轻量现有测试栈；确实缺失时增加开发期测试依赖，不增加用户运行时服务。测试结束关闭自己的进程与目录，不删除用户模型/缓存/工作区。

脚本命名目标可为 `test:ui`、`test:api`、`test:live`、`build:windows`，但必须先实现再在README声称可运行。附录tools是旧缺陷复现器，逻辑在修复后必须改成期望正确行为测试，不能要求defect_reproduced=true来通过。

## 语义评测不要只查字符串

建立24个知识案例的最小首版：6类，每类4例，开发12例/冻结留出12例。只使用公开可用或明确合成文档，不夹入私人原文；同一个规则可以有多种表达，但不给程序case_id特判。此处是要构建的评测规格，未在本审核中生成并跑完真实集。

类别：事实与范围；条件/例外/否定；假设推导；跨文档比较；长首问/上下文指代；缺失/冲突/不相关来源。

每例标注：源文件版本和定位、用户问题、必须包含的语义事实、必须保留的条件、不能推出的结论、可接受的未知与局限、期望引用集合。不以答案逐字一致为目标。

重点例：
- “有维修记录”是必要条件时，不据此保证库存与审批；假设条件足够的例子可以给条件性结论，不能把所有假设都判未知。
- 文档未规定押金，应答资料未说明，不等于免押金，更不需要重申整个借用规则。
- 两个制度比较要给比较维度，不能仅串联两段原文就通过。
- 长背景后面的实际问题不能被截掉；首问和历史追问分别评测。
- 合法但无关的引用不算支持答案；金额、时间、主体或否定变化应产生相应答案变化。

评分分开呈现检索命中/条件保留/结论支持/表达直接性/引用定位/未知校准；关键错误逐例零容忍，普通表述评分人工抽查。可离线辅助评分，但不把judge加入生产每轮，也不让judge单独证明正确。冻结留出集不能一边看失败一边改成开发题仍称holdout。

同一配置先一次baseline，再对修复运行一次；随机不稳定的关键少数例再复跑并全部记录，不能117次中挑最好一条。记录模型、索引版本与关键参数已足够，不需要另造平行账本。

## Agent评测

至少覆盖工具批次不同顺序、用户更改参数后旧预览、部分回答与部分失败、停止/重试、选第二项、已提交后的查询。判断目标结果与真实业务写入，不要求唯一工具路径。模型已提出两个工具而执行器漏一个属于代码bug，用脚本模型可确定复现；真实模型仍须覆盖自然说法，二者职责分开。

## UI和发行必查

24条详细场景见quality_cases.jsonl。原生目录选择、默认浏览器、物理中文输入法必须实际操作；合成composition事件只能证明事件处理代码的一部分。浏览器屏幕截图不能证明目录选择或IME完成。

冻结最终应用commit和完整发行目录；从干净Windows目录启动、中文路径、模型离线、重复双击、占用端口、移动数据后定位、已有工作区升级、重启复用。完整业务在同一数据目录完成，不用每次重置数据掩盖遗留状态。

依赖或外部资源缺失时标NOT_RUN/BLOCKED及最小解除条件，不把缺环境强行记成业务失败，也不说已完成正式发行。

## 性能与成本

只比较同类输入和同一机器/模型：应用可用时间、冷/热启动、模型冷/热、首个有意义进展、检索/生成各段、模型调用数与文档更新耗时。现有提交的3.609秒是特定Windows5次中位，不直接当所有机器指标。目标先是不退化和减少可解释的浪费，再定量给提升。

## 缺陷闭环与完成

每个复现失败保留输入与最小记录；修完对应测试进入正常套件，不生成另一套长期审核系统。阶段通过后再走真实入口；最后输出一份按能力分类的结果与未完成清单。证据属于同一候选或明确说明允许的文档差异，不能混用历史版本记录冒充当前完整验收。
