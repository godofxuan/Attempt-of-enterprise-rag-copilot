# 可直接开始的一课：先完成一个看得见的使用闭环

只有在当前实验室没有更具体的ESA断点时使用；若已经在L03/L06相关内容，按真实进度接续，不强迫重头。

## 今天的题目

“我修改了用途，系统显示已经保存，但还要求选择设备。这时是否已经提交？页面为什么不能说保存失败？保存后刷新又为什么应看到新值？”

## 教师先做

核对实际应用版本和学习工作区；从当前文档找到真实启动命令。使用独立合成环境，不在真实用户申请上试写。若模型尚未就绪，选仅预览的明确表单路径，不伪装成模型调用。

讲清5个对象：页面草稿、服务端事实、revision、预览、真正Ticket。不要求先背全项目术语。

## 完整操作

1. 用户亲手创建一份“仅预览”借用事项，日期选择实际允许范围，用途写为教学样例。
2. 保存用途，观察当前参数和revision；此时不选设备，说明这只是等待选择而非保存失败。
3. 选一个真正返回的候选，生成预览，核对设备与日期；不要提交。
4. 刷新并从历史重新进入，确认同一事项还在。
5. 教师带读product_router.save_facts→TaskService.facts→task_view三处，只关注输入/输出与副作用。

这条路径与本轮知识-only缺陷不同：正常准备预览当然需要日期；只问政策不需要日期。用这对例子解释依赖范围。
