## 发布时只集中走8类用户旅程

不是8个覆盖所有情况的断言，也不取代已有有效回归。平时只跑改动相关检查；发布时用这8条避免把主要时间花在巨型测试矩阵上。

1. **启动与继续**：新安装或干净副本启动；已有数据打开、模型不可用仍能设置、重启回到原会话。
2. **文档问答**：批量导入实际支持文档，看到索引就绪；普通提问/追问、打开精确来源。
3. **深入比较**：两份规则或多文档问题，实际产生子问题检索和必要补读；最终比较不遗漏关键条件。
4. **混合对话**：问政策→开始任务→补字段→改日期并问一个政策问题→选设备→预览；停止运行后继续同一事项。
5. **借用闭环**：确认申请→服务台处理→日期预留→领用→归还→同目录再次申请；缺库存时给真实备选。
6. **报修闭环**：空字段补问→自然描述→预览提交→处理中→解决→关闭；不是只验证完整表单提交。
7. **资料更新**：替换/停用/恢复文档，后续回答使用活动版本，历史回答仍能打开对应来源。
8. **最终产品交接**：历史任务和真实业务状态一致；实际模型与离线演示清楚；按README从最终副本启动，给出有效分支/commit和同步状态。

已复现的三个失败、重要的重复提交/旧版本修改和来源条件回归保留为短程序检查。不新增judge链、整库hash、平行审查层。一个journey有故障就修真实根因，不使用全新数据库和弱化断言掩盖。
