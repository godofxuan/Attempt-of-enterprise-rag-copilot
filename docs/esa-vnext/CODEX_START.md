# 一次交给Codex的启动提示词

## 推荐：连同整个压缩包发送以下内容

```text
请实际执行附件中的Enterprise RAG / Service Agent vNext长期方案，不要只回复新计划。

先找到当前真实项目工作区，读取已有AGENTS.md和当前Git状态。保留本地未提交修改、后续独立候选、活动数据库与资料；不要用GitHub历史main或10/13封存包覆盖当前成果。

将本方案放到docs/esa-vnext/。读GOAL.md、PRODUCT_ARCHITECTURE.md、ROADMAP.md；按当前阶段再读ENGINEERING_CONTRACTS.md和REFERENCES.md。把AGENTS.append.md中适用约定合并进现有AGENTS.md，保留原约定；从STATUS.template.md建立唯一STATUS.md，已有进展不能清零。

当前持续目标是完成GOAL.md定义的R1和R2，即M0—M8：稳定单入口启动、资料库与统一RAG、电脑借用完整任务、自然补充改期、精简观察—工具循环、进度与恢复、知识转任务、改动影响复用、真实备选方案、可发布演示，以及复用同一框架的合成IT报修和增量导入/反馈改进。R3不是这次无限扩张的任务。

先实际运行目前的最小入口并定位第一个真实阻塞。正常的代码、依赖、配置和交互问题自行诊断修复，不每一步都问我是否继续；发现本计划的局部设计不合适，可保留产品目标换更简单方案并记录理由。优先修改共同机制，不堆关键词、更多judge、审计框架或哈希清单。

采用当前有效的FastAPI/Pydantic/Ollama/BGE-M3/FAISS/BM25-RRF/LangGraph/SQLite；目标是产品化模块重构，不是安装全部参考平台。学习参考源码的层次和数据流，依赖API以项目实际版本为准。

在支持原生Goals的客户端中，将下面“原生Goal正文”设为当前线程目标；不支持时在当前可用会话中依同样目标执行，并保存可恢复状态。不要假称已经设置了不存在的Goal，也不要关闭客户端权限限制。

阶段结束提交可运行成果并继续下一阶段。遇到缺模型/凭据等外部阻塞，先做其余可做工作，只集中提出最小解除条件。用户中断或预算限制时保存状态；不把暂停写成完成。

最终交付实际代码、启动/恢复入口、用户可完成的操作、真实运行与未运行项、分阶段commit以及实际同步状态。按已有授权推feature分支和准备PR，不force push或擅自合并main。代码可运行比说明文件数量重要。
```

## 原生Goal正文

支持`/goal`的Codex命令界面，在方案已放到仓库后可直接发送：

```text
/goal 按docs/esa-vnext/GOAL.md和ROADMAP.md连续完成M0—M8，在当前真实代码基础上交付R1与R2：稳定单入口启动、完整知识库与有来源问答、可恢复的电脑借用Agent、知识转任务/改动影响复用/真实备选方案、共享框架的本地合成IT报修、增量导入与反馈改进。以README的实际启动、规定用户旅程和真实回执证明完成。保留本地成果与用户数据，不新增审计平台或把假模型当live；普通技术阻塞自主定位修复、阶段完成后继续。只将真正外部阻塞集中报告；达到预算或被中断时保存STATUS，不冒称完成；R3不自动执行。
```

`/goal pause`、`/goal resume`、`/goal clear`用于支持该功能的客户端控制当前目标；具体界面和可用性以用户实际客户端为准。官方文档说明Goals从Codex 0.128.0起提供，但不据此假定用户IDE插件已经支持同一命令面，也不要求在本轮强制升级客户端。[R12]

**GOAL.md是任务规范，不是后台进程。** 原生Goal属于当前线程；换线程时先读STATUS并重新指定目标。未实际激活原生Goal，就不要承诺自动跨轮继续。[R12–R14]
