# 连续实施路线：R1产品可用 → R2实际可扩展 → R3条件触发

当前Goal覆盖M0—M8，共45个工作项。编号用于定位与续接，不代表45次独立大改或45次完整模型测试。任务进展只写`STATUS.md`，本文件保持任务定义；关键设计调整在STATUS说明并同步相应章节。

## 执行总规则

先能启动，再让一条真实旅程可用，再抽取复用并增加新功能。不能跳过底座直接给页面增加一堆静态卡片；也不能把底座抽象无限扩大，直到始终没有用户可用出口。

每阶段结束产生可运行版本，继续下一阶段。遇到外部条件缺失，列出被阻塞项，先做可独立推进的工作；不得用fixture替代真实模型后把整个Goal标完成。

引用R编号见`REFERENCES.md`。不需要每项重新研究全部项目。实际已完成的能力只做兼容确认和接线，不重复实现。

**不要做：** 重建全部hash、重跑全部历史审计、整理所有无关项目、把上一版源码全覆盖到main。

## R3：未来按真实需求启动，不自动无限执行

1. 团队用户与企业身份；需要明确的组织使用场景和实际配置。
2. 一个真实外部业务系统或MCP工具适配；先确定数据和操作契约，再接通。
3. PostgreSQL、独立worker或向量索引迁移；必须有当前部署瓶颈，不按项目流行度决定。
4. 更完整前端框架；在现有组件化仍不能降低维护成本时单独实施。
5. 长期记忆、多Agent与跨任务调度；先说明具体用户收益和可独立验证的任务边界。

## Codex遇到问题的自主处理流程

### 正常技术问题：自己处理

先看实际错误、当前运行版本和调用链，尽可能缩成一个真实复现；修共用机制后跑相关检查并回到真实入口。错误位于未列出的上游模块时允许进入该模块，不因任务清单没写到就停下。

两次无进展补丁后改变诊断方法：检查数据和配置是否来自同一运行、是否真的加载了所改源码、事件循环是否阻塞、模型是否支持协议。不要继续堆catch、关键词或延长timeout掩盖根因。

### 设计发现：调整实现，保持目标

发现现有模块已经能完成计划能力就复用；发现统一接口过大就缩小；发现某个抽象只有一个调用方就先保留直接代码。记录一个简短决定，避免保留两套长期并行实现。

### 外部阻塞：集中、具体、不中断无关工作

缺模型/账户/生产权限/确切业务规则时，标明影响哪些工作项，先完成不依赖它的实现。只提出最小解除条件，不反复要求用户重新打包整个项目。明确区分“代码完成、未live运行”和“功能已验证”。

### 如何恢复一个新会话

读GOAL、已有AGENTS和STATUS；检查当前工作区是否与STATUS记录一致；看最近一次实际错误和下一步；继续当前阶段。无需重新研究全部高星项目、重新哈希整包或创建新的平行执行计划。

## 工作分配建议

串行主线优先。若Codex确实有可用子任务执行能力，可将参考源码阅读、隔离的前端样式、独立文档修复作为有明确文件边界的任务；核心数据迁移、Store、图和公共契约由一个主执行流整合。不能让多个执行者同时修改同一schema后再依赖模型“猜”哪个版本正确。

本方案不要求多Agent开发编排；单个Codex持续执行完全可以完成同样目标。
